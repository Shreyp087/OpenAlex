A SUPPORT CASE, STEP BY STEP.

ILLUSTRATIVE WORKFLOW / REAL EVIDENCE

Imagine a library catalogue card with one paper’s DOI and authors, but another paper’s title. SourceCheck opens the underlying records side by side, so a reviewer can see where they disagree.

Walk through this recorded case +

  1. Paste the record ID.

    Enter W4385245566. The captured example preserves what was observed on 17 September 2026.

  2. Choose “Check live.”

    Fetch the current OpenAlex record and DOI registry metadata. The result may change as sources are updated; failed requests remain visible.

  3. Compare the source records.

    In the captured case, five DOI records contain three different main titles. Check authors and publisher pages too. The three Zenodo entries include legitimate version relationships; multiple DOIs alone do not prove a bad merge.

  4. Export the evidence packet.

    Keep the findings, raw responses, retrieval times, and hashes together. A reviewer can check the same observations instead of reconstructing them from a screenshot.

MAINTAINER-ONLY FOLLOW-UP

An OpenAlex maintainer would investigate how the sources were linked, decide whether any correction or split is justified, apply it through their authorized workflow, then recheck the record. SourceCheck does not perform or submit that correction. No ticket has been submitted for this example.

05 / AN HONEST VALUE ASSESSMENT

EVIDENCE YOU CAN RECHECK.

USEFUL TODAY

SourceCheck collects source disagreements and their receipts in one repeatable check. It may reduce the manual work of assembling evidence for a support investigation. The captured case demonstrates that collection and replay.

NOT YET PROVEN

OpenAlex already has AI-assisted ticket validation and correction. I have not assessed its internal tools. This project does not establish a missing internal capability, a novel matching method, or measured time savings.

Where the checks can mislead +

Versions, translations, and alternate titles can trigger flags without an error. Matching titles can hide wrong authors. DOI registry metadata is evidence, not guaranteed ground truth.

For example, punctuation removal makes “C++ for Biology” and “C for Biology” compare equal. A separately stored subtitle can cause a harmless disagreement. These are illustrative rule limitations, not observed OpenAlex defects.

Automatic checks compare titles and canonical DOI values. Names and typed relationships provide context, not an identity decision. A check reads at most six source DOIs; extra sources or failed reads leave gaps. Publisher-page and nine-ORCID verification belong to this archived case, not the general live checker.

How I would test whether it saves useful work +

Proposed evaluation—not completed: take 20 consecutive eligible metadata tickets and form ten pairs by type and complexity before checking results. Randomly assign one ticket per pair to the team’s current agents and tools, and the other to that same process plus SourceCheck. Balance engineers across both methods; nobody handles the same ticket twice.

Measure active review time, confirmed additional findings, unhelpful flags, and whether another reviewer can reproduce the evidence. Use independent reviewers who do not know which method produced each decision. Include failures and unresolved cases; twenty tickets provide exploratory evidence, not a general accuracy estimate.

If it adds review time without useful new evidence, do not adopt the extra interface. Keep the verified case and reusable checks if they help the existing workflow.
